# Databento за общей MCP-платформой

## Последнее правило Standard — 2026-11-17

Для исторических данных CME/CBOT/NYMEX/COMEX в `GLBX.MDP3`, включённых в подтверждённый для текущего ключа Standard, Gateway пропускает автоматический `get_cost` и денежное согласование. Вне покрытия или без назначения Standard положительная оценка любой величины требует разового подтверждения в кабинете. Эта политика действует с 17 ноября 2026 года на Platform `f380ac7` и Node `38c5e76`. Таблица ниже включает дополнение к этому развёртыванию. Локальный режим описан в [контракте stdio и single-user HTTP](standard-cme-entitlement-plan.md).

Покрытие определяет версия правил `1` профиля `cme_standard`. [Публичная таблица Databento Standard](https://databento.com/pricing).

| Уровень | Schemas | Диапазон |
|---|---|---|
| L0 | `ohlcv-1s`, `ohlcv-1m`, `ohlcv-1h`, `ohlcv-1d`, `definition`, `statistics`, `status` | Вся доступная история; «16+ years» не означает rolling-границу ровно 16 лет |
| L1 | `mbp-1`, `tbbo`, `bbo-1s`, `bbo-1m`, `trades`, `cmbp-1`, `cbbo-1s`, `cbbo-1m` | Последние 12 календарных месяцев |
| L2 | `mbp-10` | Последний календарный месяц |
| L3 | `mbo` | Последний календарный месяц |

20 ноября 2026 года в исходники облачного коннектора добавлены три схемы L1. В `GLBX.MDP3` схема `cmbp-1` объединяет прямые и подразумеваемые котировки CME, а `cbbo-1s` и `cbbo-1m` дают срезы этой книги. Тариф Standard включает все три за последние 12 месяцев. После обновления коннектора к ним применяется существующее назначение Standard для ключа. [Тариф CME Standard](https://databento.com/pricing/) и [описание книги CME](https://databento.com/docs/datasets/glbx-mdp3#implied-book).

Границы вычисляются относительно точного текущего UTC-времени с корректировкой конца месяца. Date-only start означает полночь UTC: часть граничного дня до точной границы не считается покрытой. При date-only start пропущенный end означает следующий UTC-день; остальные запросы без end требуют оценки. Другие datasets и неизвестные schema не получают покрытие автоматически. Технические ограничения direct response, времени, памяти, параллельности, квоты кэша и прав продолжают действовать. Platform Reference/batch остаются выключенными; этот этап не добавляет массовый экспорт.

## Доверенное назначение и проверка каждого подзапроса

Назначение Standard — заявление пользователя, записанное администратором для текущего ключа и ревизии его encrypted credentials. API поставщика не проверяет его автоматически. Сохранение/удаление ключа в Gateway сбрасывает назначение; повторное добавление прежнего ключа не включает план молча. Доступность `metadata.get_dataset_range` не доказывает подписку или отсутствие доплаты.

Gateway передаёт optional `subscription` в подписанном private body, отдельно от MCP arguments:

```json
{"subscription":{"plan":"cme_standard","policy_version":1,"credential_sha256":"<SHA-256 текущего ключа>"}}
```

Node строго проверяет поля, план, версию и SHA переданного `api_key` до обращения к поставщику. Live и metadata не получают historical subscription assertion. При корректном назначении transport guard классифицирует **каждый фактический** `/v0/timeseries.get_range`, включая скрытые загрузки quote/bars/smile. Покрытый запрос исполняется без автоматического cost preflight. Для непокрытого запроса остаётся `get_cost` с идентичными параметрами; ошибка оценки не становится нулём. Нулевая оценка позволяет загрузку, положительная требует действующего разового допуска.

`get_cost` учитывает flat-rate скидки, но не доказывает дополнительное net списание после credits. Покрытая ветвь не переписывает положительную оценку в ноль: она вообще не вызывает automatic preflight. Непокрытая ветвь использует оценку поставщика. [Metadata get_cost](https://databento.com/docs/api-historical/metadata/metadata-get-cost).

Node переводит текст десятичной оценки поставщика в целые миллионные доллара, включая экспоненциальную запись. Оценка округляется вверх, разрешённая сумма вниз. Ровно подтверждённая сумма допускает один вызов. Параметры инструментов с целочисленными счётчиками ограничены диапазоном точных целых чисел JavaScript.

Optional `subscription_covered_requests` в private cost summary — целое число 0–10000, учитывающее допущенные попытки покрытой загрузки, включая завершившиеся ошибкой. Это не число успешно полученных результатов. Это счётчик операций, не сумма денег и не подтверждение provider billing. Денежные оценки summary относятся к запросам вне покрытия; отсутствие `get_cost` не выдаётся за полученную от поставщика оценку `$0`.

## Разовые подтверждения и техническое состояние

В Gateway режим новых и прежних policy по умолчанию — `historical_cost_mode=confirm_extra`. Старые request/day суммы в этом режиме не дают автоматического денежного допуска. Совместимый `budgeted` может применяться только при явном выборе; это не правило текущего владельца. Без разового подтверждения allowance положительных непокрытых запросов равен нулю; `paid_downloads_enabled=false` запрещает платную загрузку даже при назначенном плане для других покрытых запросов.

Все платные внутренние части одного внешнего MCP-вызова суммируются. Подтверждение привязано к владельцу, точным параметрам, максимальной оценке, сроку и текущей ревизии credentials; используется один раз. Изменение ключа/политики не позволяет повторно использовать прежнее разрешение. Gateway сохраняет leases и неопределённые резервы в `budget.sqlite3`; миграция не списывает их в ноль. Timeout, обрыв и частичный результат не доказывают отсутствие расходов. Автоматических повторов загрузки нет; ручной повтор может снова тарифицироваться.

Node сохраняет атомарные anti-replay nonce claims в отдельном persistent volume до допуска платной загрузки. В нём нет ключей, ответов поставщика, общего data cache или HOME пользователей. Перезапуск/ошибка не освобождают допуск для повторного использования. Backup/restore сохраняет согласованное состояние Gateway ledger и nonce records; пустой nonce-каталог допустим только после истечения всех старых JWT. Это техническое состояние, не Research Storage.

## Live и реальная приёмка

С 20 ноября в исходниках private-службы доступен `stream_bba` для лучшей покупки и продажи одного инструмента в `GLBX.MDP3`. Старый локальный `LiveChainConsumer` держит одно соединение Raw TCP/DBN с подпиской `mbp-1`. Новый изолированный процесс использует его между запросами MCP.

1. Передайте `{"action":"start","symbol":"ES.v.0","stype_in":"continuous"}`. Ответ содержит `stream_id`. Статус `connecting` означает начало подключения.
2. Передайте `action=read`, полученный `stream_id` и `after=0`. Для следующей страницы используйте `next_cursor`. Выдаются изменения цен и объёмов лучшего уровня с идентификатором инструмента и временами события, приёма Databento и приёма коннектором. Пустая страница возможна в тихий рынок. Снятая сторона получает `null`.
3. Завершите подписку действием `stop`. Буфер хранит 4096 изменений, страница содержит до 100. При отставании `missed_events` показывает точное число вытесненных изменений подписки. Прочитанная страница сопровождается DBN-метаданными и оригинальными записями выбранных изменений. Ошибка поставщика и закрытие сокета завершают поток. Автоматического переподключения нет.

Подписка привязана к workspace, владельцу, личному ключу и его ревизии. Допускаются две подписки владельца и двенадцать на процесс. Сокет освобождается через 45 секунд без обращения или после пяти минут работы. Для нового периода нужен новый `start`. Допуск подписки и тарификация Live определяются поставщиком.

Прежний `get_live_futures_quote` возвращает первое подходящее двустороннее обновление и закрывает сокет. Оба Live-метода используют права ключа на dataset. Оценка Historical к ним неприменима. [Live API](https://databento.com/docs/api-live/basics.md), [MBP-1](https://databento.com/docs/schemas/mbp-1).

Пользователь явно разрешил ограниченную реальную проверку MCP по нескольким фьючерсам, опционам и типам данных на своём ключе. Это не разрешает покупку подписок, автоматическое подтверждение доплат или публикацию ключей/лицензированных ответов и выгрузок. Реальные запросы не включаются в обычные тесты/CI. Offline fixtures проверяют границы покрытия, отсутствие preflight внутри него, обязательное подтверждение вне него, mixed calls, смену ключа/политики, одноразовость, частичный результат и перезапуск. Один успешный Live-вызов не доказывает всю матрицу, точный биллинг или GUI-приёмку всех клиентов.

## Исходный platform baseline — 2026-10-23

Историческая запись: ограничения zero-only/Live ниже заменены последними разделами выше. Она не описывает текущую политику Standard.

2026-10-23 пользователь поручил подключить существующий коннектор к единому авторизованному MCP Gateway. Локальный stdio и прежний single-user remote HTTP сохраняются. Новый compiled entrypoint `dist/mcp/mcp/platform.js` предназначен только для private RPC внутри платформы; он не публикует собственный MCP endpoint и не заменяет внешний OAuth Gateway.

Служба предоставляет `GET /healthz`, `POST /v1/tools` и `POST /v1/call` на внутреннем порту 8002. `HOST` задаётся `0.0.0.0` внутри контейнера, `PORT=8002`. `DATABENTO_PLATFORM_SIGNING_KEY_FILE` указывает на отдельный raw-ключ ровно 32 байта. Запросы связаны с короткоживущим HS256-контекстом Gateway, workspace, действием и SHA-256 тела. Ключ поставщика поступает по private RPC из зашифрованного личного профиля, а не из глобального `.env`.

Каждая операция создаёт отдельный дочерний процесс с очищенным окружением и собственными HOME/XDG/TMP. Дедлайн 120 секунд, максимум четыре операции одновременно. Production Compose ограничивает всю службу 2 GiB памяти без дополнительного swap и 128 PID. Доступны metadata, symbology и session info; historical/quote/bars/smile допускаются только после нулевого cost preflight фактического запроса. Live/reference/batch не предоставляются. Временный профиль удаляется; общего пользовательского дискового volume нет.

Уточнение объёма от 2026-10-23: универсальный Research Storage и журнал исследований отложены. Тела upstream читаются потоково с общим лимитом 16 MiB и 64 KiB для ответа с ошибкой; неверный UTF-8 или превышение отменяет поток без повторной загрузки. BOM сохраняется в оригинале и хеше. Native MCP-ответ и точные decoded HTTP bodies с хешами передаются Gateway для рабочего кэша Databento в пространстве владельца. Кэш нужен для страниц результата, экспорта и чтения оригиналов; отдельный сервис Storage, исследования и ревизии для этого не требуются. Доступ к кэшу требует разрешённого и включённого коннектора. CSV сохраняет строки/происхождение; неизвестное покрытие не объявляется полным. Provider-ошибки/ключи/пути не выводятся в публичные ошибки.

`deploy/Dockerfile.platform` выполняет multi-stage Node 24 build с `npm ci` по существующему lock и production dependencies. Dockerfile-specific allowlist исключает `.env`, Git, пользовательские базы и локальный `node_modules`. Runtime непривилегированный и read-only, `/tmp` временный; внешние порты не публикуются, provider HTTPS доступен через egress-сеть.

Поддерживаемая сборка выполняется платформенным `deploy/build_image.py` из `git archive` точного Databento source SHA. Генерируемый `SOURCE_MANIFEST.json` включается в runtime и проверяется против Git-архива, затем используется immutable image ID или repository digest. Прямой `docker build` из изменяемой рабочей папки не объявляется подтверждённой source-сборкой. Source manifest не является независимым ревью/подписью. Существующие незакоммиченные пользовательские изменения не сбрасываются и не подмешиваются в snapshot автоматически.

Полная актуальная инструкция, Compose overlay/profile, bootstrap и [контроль расходов](https://github.com/dqdp/marengo-mcp-platform/blob/main/docs/SPENDING_CONTROL.md) находятся в самостоятельной Marengo MCP Platform; доступ требует прав к приватному репозиторию. Прежняя [инструкция в COT Research](https://github.com/dqdp/cot-research/blob/main/docs/DATABENTO_PLATFORM.md) сохранена как история переноса. Авторизация и личные секреты принадлежат общей платформе; результаты — техническому кэшу коннектора. Успешные offline-тесты/CI не заменяют реальное HTTPS-развёртывание, независимые ревью и облачные ChatGPT Work/Claude Cowork проверки. Платные тестовые загрузки данным документом не разрешаются; эксплуатационная policy применяется только после отдельного развёртывания и явного включения.

## Проверка переноса 2026-10-23

В изолированной ветке сохранены версия пакета 1.3.0 и диапазоны зависимостей; runtime lock обновлён в пределах совместимых версий SDK 1.x. На Node 24.22.1 прошли 710 тестов, сборка MCP/skills, stdio/HTTP/skills/private-entrypoint smoke и npm pack dry-run. Реальные Databento API не вызывались. `npm audit --omit=dev` после установки показывает 0 уязвимостей; полный audit с dev-зависимостями содержит 5 замечаний (faker/adm-zip/Vitest dependency chain), требующих отдельной проверки обновления диапазонов. Это не объявляется нулём уязвимостей всего дерева. Исходная пользовательская папка с незакоммиченными изменениями сохранена. Реальные облачные клиенты, целевой HTTPS/OIDC и обязательное Anthropic-ревью остаются отдельными условиями.
